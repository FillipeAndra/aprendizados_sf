
- Usado para controlar quem tem acesso a sua organização, quem pode acessar os aplicativos alocados na sua organização, e por meio de qual interface.

- serve para unificar os logins em um único acesso para não precisar ficar criando diversos acessos para cada aplicativo dentro do Salesforce

- isso se aplica também a certas aplicações externas que aceitam a identidade Salesforce

## Funcionalidades

### Single sign-on (acesso único)

- permite a unificação de logins em diferentes plataformas associadas, usando apenas um único login

- EX: Google cloud, office 365, outras organizações Salesforce, etc.

- permite o controle de acesso à informações sensíveis em 1 só lugar

- os passos para configurar essa funcionalidade para um usuário é : criar um ID da federação para cada usuário desejado, ativar o SSO nas configurações do Salesforce, configurar a Salesforce no provedor de SSO e verificar se tudo está funcionando

#### 1 - Criação de um ID de federação (Federation ID)

- ID de identificação único interno na organização (se o usuário fizer parte de múltiplas organizações Salesforce é ideal que ele tenha o mesmo federation ID em cada organização)

1) Acesse a organização como admin, vá em setup, pesquise por Users e selecione a opção

2) Entre no usuário que deseja criar o ID e para a sessão de Single Sign On Information

3) lá coloque o id que segue o mesmo padrão de criação de login de usuário. Após finalizado salve.

#### 2 - Configurar o provedor de SSO dentro do Salesforce

- tanto no provedor SSO quanto no Salesforce o usuário deve ter o mesmo Federation ID

- Primeiro se configura o provedor SSO dentro da Salesforce, despois é feito o processo contrário

- Ambos se comunicam usando o protoclo SAML

1) Primeiro vá para o Provedor De SSO e pegue o certificado para comunicação

	- Neste cenário usando o Axiom acesse o  [https://axiomsso.herokuapp.com](http://axiomsso.herokuapp.com/)

	- Entre na página de SAML Identity provider & Tester

	- Baixe o certificado provedor de identidade

2) Como admin vá para setup e pesquise por **single sign-on settings** no quick find

3) Clique em editar e selecione SAML Enable e salve.

4) Ainda dentro dessa tela de **single sign-on settings** clique em **New** no sub menu de **SAML Single Sign-on settings** 

5) os passos nessa tela são:

	- Colocar o nome desejado
	
	- Colocar a URL do provedor SSO
	
	- Colocar o certificado do provedor
	
	- Colocar o método de assinatura (neste exemplo é: RSA-SHA1)
	
	- Selecionar no SAML Identity type (Neste caso é: **Assertion contains the Federation ID from the User object**)
	
	- Selecione no SAML Identity location: **Identity is in the NameIdentifier element of the Subject statement**

	- Selecione no Service Provider Initiated Request Binding: HTTP Redirect

	- no Entity ID coloque a url do seu ambiente suando o https. EX: https://mydomain-dev-ed.develop.my.salesforce.com

6) Salve suas modificações

#### 3 - Relacione o seu provedor de identidade com o Salesforce

1) No caso do Axiom, é preciso entrar nele [https://axiomsso.herokuapp.com](http://axiomsso.herokuapp.com/)

2) Clicar em SAML Identity Provider & Tester

3) Clicar em generate a SAML response e inserir os seguintes valores:

	- SAML Version 2.0

	- Em Username or Federation ID: colocar o Federation ID do usuário desejado

	- Em Issuer colocar: https://axiomsso.herokuapp.com

	- Em recipient URL: Colocar a login URL presente na parte de baixo do SAML Sign-On Settings criado, dentro do campo Endpoints

	- Em Entity Id: Colocar o Entity ID presente na mesma última página citada

#### 4 - Verificando funcionamento

1) Na mesma página do final do último comando citado anteriormente vá até o final e clique em **Request SAML Response**

2) Clique em login. Se der certo, você entrou na página do usuário cadastrado

### External Client Apps

- Acesso a apps sales force de terceiros, apenas utilizando uma única conta

- Isso funciona quando o acesso a apps externos são configurados para SSO (Single sign-on)

### Social sign-on

- funcionalidade para permitir o login na sua organização salesforce ou aplicações criadas relacionadas ao ambiente, usando logins de outras plataformas sociais reconhecidas, como google, facebook, linkedin, etc.

- as plataformas que aparecem no momento da realização de login dependem da configuração realizada pela(o) admin que libera ou não certas plataformas aceitas pela salesforce

### MFA (Multi Factor Authentication)

- realização de uma verificação de 2 fatores (2FA) para realizar o login no ambiente salesforce usando app Salesforce Authenticator

### Meu domínio (My domain)

- ferramenta que permite criar um domínio de nome único para facilitar o acesso ao ambiente salesforce.

- o prefixo da URL fica a critério do(a) admin, mas a url tem que finalizar com my.salesforce.com

- Essa funcionalidade é obrigatória que seja configurada para permitir as funcionalidades de social sign-on, single sign-on e caso se tenha várias organizações salesforce da empresa que se vinculem, como em caso de um organização salesforce para cada filial de uma empresa que precisa que se essas orgs se comuniquem.

- serve também para permitir a customização da página de login da organização

#### editando my domain

1) Usando o usuário admin acesse o setup e no quick find pesquise por my domain

2) dentro dessa página é possível editar o campo de  my domain details para mudar o pré-fixo do domínio 

3) No **Routing and policies** é possível :

	- selecionar de onde as pessoas podem acessar (somente de dentro do pais ou se também de fora), 
	- pode impedir login via SOAP API
	- impedir o login de páginas gerais como login.salesforce.com e welcome.saleforce.com, permitindo somente caso a pessoa saiba a URL verdadeira da organização 
	- e pode pedir a autorização de cookies do salesforce

4) No **Redirections** é possível configurar para capturar os logs e impedir as requisições de API que não tenham a URL específica da organização

5) Authentication configuration: serve para permitir acesso via navegador do dispositivo IOS ou android, e o compartilhamento da sessão do navegador em ambos os casos. Assim como:

	- selecionar o tipo de página de login
	- o tipo de login se é SAML SSO associado ao trailhead
	- logo da empresa na pagina de login
	- cor de fundo da página de login 
	- e o link presente nos quadros à direita
### Centralized user accounts

- auxilia no controle do acesso dos usuários, permitindo em uma interface, a liberação ou revogação de acesso de um app para um usuário, assim como a proibição de acesso geral ao salesforce por exemplo em caso do usuário não saber qual o domínio do ambiente.

### App Launcher

- é possível configurar quais apps ficam disponíveis para cada usuário a tela do app Laucher usando o Salesforce Identity

## Controle de acesso SalesForce identity


### Colaboradores

- tem que permitir o login de maneira facilitada para permitir uma maior agilidade dos usuários

- Tem a necessidade de liberar um conjunto maior de acessos para que as demandas sejam efetuadas, entretanto deve haver também um controle sobre esses acessos.

- O processo de integração com aplicativos como google drive, office 365 é efetuado usando SSO e as aplicações ficam disponíveis para os usuários na parte de App Launcher.

- Através do salesforce Identity é possível fazer gestores aprovarem ou recusarem requisições de acessos realizadas por seus subordinados e como admin é possível permitir acesso ou remover no momento desejado.

### Consumidores e parceiros

- consumidores e parceiros devem também ter acessos a sua organização para poder consumir ou produzir em conjunto

- os acessos são mais restritos do que o de um colaborador

- O salesforce Identity permite o uso de contas social sign-on, o que facilita para pessoas de fora da organização terem acesso ao que elas precisam, sem precisar entrar em contato para obter uma conta só para comprar ou fazer negócios

- Através desse processo é possível manter um controle de quem está acessando, mantendo as informações de tal usuário unificada e facilitando entender sua personalidade, possibilitando a construção de um melhor planejamento de negócio ou venda para a organização.

- permite uma melhor maneira de manter contato com o cliente ou parceiro, permitidno a realização de envio de e-mails e realização de campanhas de marketing

## Linguagens e protocolos associados à identificação

- Alguns dos protocolos utilizados no processo de autenticação são o SAML (Security Assertion Markup Language), o OAuth 2.0 e o OpenID Connect 

- o serviço ao qual o usuário logga é o identity provider e o serviço que ele quer acessar com esse login é o service provider

### SAML 

- É o protocolo responsável pela realização de Single Sign-on (SSO), onde um login do aplicativo atual, lhe permite acesso a outras aplicações externas

- realiza a comunicação entre o serviço solicitado para acessar e questiona para o serviço onde o login foi feito, se o usuário tem autorização para acessar os serviços e se ele está logado, caso sim, algusndos dados dos dados do usuário são compartilhados como o serviço.

- assertion (afirmação) é o processo do envio desses dados sobre o solicitante do serviço para o serviço

- A Comunicação por meio do SAML é feita via XML

### OAuth 2.0

- É um protocolo aberto usado para o envio de dados entre aplicações

- ele serve para realizar a verificação de identidade para poder liberar a comunicação entre as aplicações

- Usado em API para realizar a comunicação de dados

### OpenID Connect

- usado focado como o SAML para o processo de autenticação entre diferentes aplicações, mas mais moderno, geralmente usado para comunicação com redes sociais como contas google e outras.

- usado bastante no processo de Social Sign-On
